# Phase 5：搜尋、標籤篩選、多視圖（列表 / 甘特圖） 設計文件

> 討論日期：2026-09-10
> 狀態：**Spec only — 本文件僅記錄設計決策，待確認後進入 plan + 實作階段**

## 背景

Toolbar 目前有搜尋圖示、篩選圖示、「Dashboard／議題看板／列表視圖／甘特圖」四個分頁按鈕，皆為靜態 UI、無實際功能。本次 Phase 5 把這四塊補上真正的功能，範圍較大，拆成四個獨立子功能依序實作：**搜尋 → 標籤篩選 → 列表視圖 → 甘特圖**。每個子功能各自可獨立驗收，彼此不互相依賴（除了篩選/搜尋條件在切換視圖時共用同一份過濾邏輯）。

## 已確認的設計決策

### 1. 搜尋

| 決策點 | 選擇 |
|---|---|
| 搜尋範圍 | 只搜尋任務標題（`task.title`），不含描述/留言 |
| 比對方式 | 不分大小寫的子字串包含比對（`title.toLowerCase().includes(query.toLowerCase())`） |
| 實作方式 | 純前端即時過濾，不新增後端 API；`Board` 元件內既有的 `tasks` 陣列先套用搜尋條件再分配到各欄位（`tasksByColumn`） |
| UI 互動 | 點擊 Toolbar 的搜尋圖示，展開一個輸入框（inline 展開或彈出皆可，實作時依現有 Toolbar 版面決定），輸入時即時過濾；清空輸入或收合搜尋框時恢復顯示全部任務 |
| 影響範圍 | 看板（桌面/手機模式）、`/done` 頁面、之後新增的列表視圖／甘特圖皆套用同一個搜尋條件（透過共用的 state/context 或 URL query，待 plan 階段決定技術做法） |

### 2. 標籤篩選

| 決策點 | 選擇 |
|---|---|
| 篩選維度 | 只篩選標籤（`TagType`：`github`/`issue`/`bug`/`pr`，即既有 `TAG_OPTIONS`） |
| 篩選邏輯 | 複選；任務只要標籤集合中「至少命中一個」被選取的篩選標籤，就顯示（OR 邏輯，非 AND）；未選取任何標籤時顯示全部任務 |
| 實作方式 | 純前端過濾，比照搜尋做法 |
| UI 互動 | 點擊 Toolbar 篩選圖示，彈出一個下拉面板，內含 `TAG_OPTIONS` 的 checkbox 列表；面板外點擊關閉；已選取的標籤數量可在篩選圖示旁顯示小徽章（例如篩選圖示右上角圓點或數字） |
| 與搜尋的組合 | 搜尋與標籤篩選同時套用時為 AND 關係（先過濾標籤，再套用搜尋字串，或反過來，結果等價） |

### 3. 列表視圖

| 決策點 | 選擇 |
|---|---|
| 呈現形式 | 表格形式，一列一筆任務，不分欄位分組（所有任務攤平在同一張表） |
| 顯示欄位 | 標題、欄位（顯示欄位中文名稱，如「處理中」）、優先級、負責人 |
| 互動 | 點擊任一列開啟既有 `TaskDrawer` 編輯；不支援拖拉排序或拖拉換欄 |
| 切換方式 | 點擊 Toolbar 的「列表視圖」分頁按鈕，畫面主要內容區從看板換成表格；「議題看板」分頁按鈕點回看板 |
| 資料來源 | 沿用 `Board` 已載入的 `tasks` 陣列，套用同一套搜尋/標籤篩選條件 |
| 排序 | 不需要可排序表頭（點擊欄名排序），維持後端回傳順序即可（範圍外，不做） |

### 4. 甘特圖

| 決策點 | 選擇 |
|---|---|
| 新增資料欄位 | `Task` 新增 `dueDate?: string`（ISO 日期字串 `YYYY-MM-DD`，選填），資料庫新增對應欄位 `due_date` |
| 日期輸入位置 | `TaskDrawer` 新增「預計完成日期」欄位（`<input type="date">`），選填 |
| 甘特圖橫條範圍 | 每筆任務畫一條橫條，起點為 `createdAt`（建立日期），終點為 `dueDate`；若任務沒有填 `dueDate`，該筆任務**不在甘特圖中顯示橫條**（但仍可能出現在任務清單軸上，或直接從甘特圖清單排除——實作時決定，傾向排除以避免無意義的橫條） |
| 呈現形式 | 橫軸為日期刻度，縱軸為任務清單（一列一筆任務，比照列表視圖的縱向排列），每列右側依日期位置畫一條橫條 |
| 檢視粒度 | 日期軸可切換「週檢視」／「月檢視」，透過畫面上的簡單切換按鈕（例如兩個 tab 或 toggle） |
| 切換方式 | 點擊 Toolbar 的「甘特圖」分頁按鈕進入 |
| 互動 | 點擊任務列（清單側或橫條）開啟既有 `TaskDrawer` 編輯，可在其中修改 `dueDate`；不支援拖拉橫條調整日期（範圍外） |
| 技術選型 | 不引入額外的甘特圖 npm 套件（如 `frappe-gantt`、`gantt-task-react`），用純 CSS/SVG/Tailwind 手刻簡易橫向時間軸，避免額外依賴與樣式客製化成本；若手刻在 plan 階段評估後發現複雜度過高，屆時再與使用者討論是否改用套件 |

## 架構影響（規劃）

### Toolbar 分頁狀態管理

- 目前 `Toolbar.tsx` 的四個分頁按鈕（`Dashboard`/`議題看板`/`列表視圖`/`甘特圖`）是純靜態陣列渲染，寫死「議題看板」為選中狀態。改為由 `Board` 元件管理一個 `activeView: 'board' | 'list' | 'gantt'` state（`Dashboard` 分頁維持無功能，點擊無反應——範圍外，不在本次實作），往下傳給 `Toolbar` 決定哪個分頁高亮，並依此切換主內容區渲染。

### 搜尋與篩選狀態

- 新增 `searchQuery: string` 與 `selectedTagTypes: TagType[]` 兩個 state，放在 `Board` 元件（因為看板/列表/甘特圖都在同一個路由 `/` 底下、同一個 `Board` 元件樹內共用）。
- 抽出一個共用的過濾函式 `filterTasks(tasks, searchQuery, selectedTagTypes)`，三種視圖（看板/列表/甘特圖）都呼叫同一個函式取得過濾後的任務清單，避免邏輯重複。
- `/done` 頁面本次不套用搜尋/篩選（範圍外，`/done` 是獨立路由/獨立 state，之後如需要可再擴充）。

### 元件拆分

- `src/components/SearchBox.tsx`（新增）：Toolbar 內的搜尋輸入框元件。
- `src/components/TagFilterPanel.tsx`（新增）：篩選面板元件（下拉面板 + checkbox 列表）。
- `src/components/ListView.tsx`（新增）：列表視圖表格元件。
- `src/components/GanttView.tsx`（新增）：甘特圖元件。
- `Toolbar.tsx`：新增 `activeView`/`onViewChange` props 控制分頁高亮與點擊行為；搜尋/篩選相關 UI 直接掛載在 `Toolbar` 內（或由 `Toolbar` 提供插槽，`Board` 傳入 `SearchBox`/`TagFilterPanel` 元件——實作時依現有 `Toolbar` 結構決定較簡潔的做法）。

## 範圍外（本次規劃不涉及）

- 不涉及搜尋描述/留言內容（只搜標題）。
- 不涉及標籤篩選以外的篩選維度（優先級、負責人篩選皆不做）。
- 不涉及列表視圖的表頭排序功能。
- 不涉及甘特圖橫條的拖拉調整日期功能。
- 不涉及 `Dashboard` 分頁的任何功能實作（維持無反應的靜態按鈕）。
- 不涉及 `/done` 頁面套用搜尋/篩選條件。
- 不涉及甘特圖引入第三方套件（優先手刻，除非 plan 階段評估後認為必要且使用者同意）。
