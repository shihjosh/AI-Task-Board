# 已完成獨立頁面 + 拖放標記完成區 設計文件

> 討論日期：2026-09-10
> 狀態：**Spec only — 本文件僅記錄設計決策，待確認後進入 plan + 實作階段**

## 背景

前一輪工作（手機版響應式版面）合併後，使用者回報桌面版看板「跑版」。實際重現後確認根本原因：

- 四欄式看板（等待認領/處理中/等你確認/已完成）固定寬度 `4 × 320px + 3 × 16px(間距) = 1328px`。
- 常見桌面視窗寬度（例如 1280px）放不下四欄，且看板容器用了 `justify-center` 置中。
- `justify-center` 在內容超出容器寬度時會**左右對稱溢出**，但瀏覽器的水平捲動只能往正方向捲（`scrollLeft` 最小為 0），導致左側溢出的部分永遠捲不到——「等待認領」欄左邊被永久裁掉一截，視覺上像是跑版。

在跟使用者討論多個修正方向（修正裁切 bug / 把手機單欄模式的斷點拉高）後，使用者選擇了更徹底的方案：**看板主頁面不再顯示「已完成」欄，改成獨立頁面**，同時保留拖拉的操作習慣。

## 已確認的設計決策

| 決策點 | 選擇 |
|---|---|
| 看板主頁面欄位 | 只顯示三欄：**等待認領 / 處理中 / 等你確認**。「已完成」欄位從主看板的渲染中移除（桌面版多欄排列與手機版單欄標籤切換都只列這三欄） |
| 三欄後的寬度 | `3 × 320px + 2 × 16px = 1024px`，遠小於常見桌面視窗寬度，不會再發生裁切問題；本次不需要再修正 `justify-center` 的 safe-center 問題 |
| 「已完成」資料 | **保留**，不刪除既有 `done` 狀態的任務與資料庫欄位；只是不在主看板頁面渲染 |
| 標記完成的操作方式 | 頁面底部固定一條橫向長條（例如「拖曳到這裡標記完成」），作為 `useDroppable` 的拖放目標。使用者把卡片從「等你確認」（或任一欄）拖到這條長條上，該任務的 `columnId` 更新為 `done` |
| 底部長條的顯示時機 | 平時（沒有拖拉動作時）以較不顯眼的樣式顯示在頁面最底部；拖拉進行中（`DndContext` 的 `activeTask` 不為 `null`）時視覺上更明顯（例如變色/放大），提示使用者這是有效的拖放目標，提升可發現性 |
| 已完成任務的顯示位置 | 新增獨立頁面 `/done`，列出所有 `columnId === 'done'` 的任務 |
| 路由方式 | 引入 `react-router-dom`（新增 npm 依賴），兩個路由：`/`（看板主頁）與 `/done`（已完成列表頁）|
| 如何進入 `/done` 頁面 | 在 `Toolbar` 加入一個連結/按鈕（例如「已完成」文字連結，可顯示已完成任務數量），點擊導覽到 `/done` |
| `/done` 頁面的任務呈現方式 | 沿用現有 `TaskCard` 元件風格顯示清單（不需要是看板欄位形式，用簡單的垂直清單即可），點擊任務可開啟既有的 `TaskDrawer` 編輯視窗（複用度高、不必重新設計表單） |
| `/done` 頁面是否可以把任務移出 | 可以——沿用既有的 `TaskDrawer` 內「欄位」下拉選單即可將任務改回其他欄位，不需要在 `/done` 頁面新增額外的操作 UI |
| 手機版模式下的底部拖放長條 | 手機模式下拖拉本來就不是主要換欄手段（已有「移動到...」選單），底部拖放長條在手機模式下**不渲染**，避免與手機版標籤列爭奪畫面空間；手機版要標記完成，改用 `TaskCard` 既有「移動到...」選單選擇「已完成」（此選單原本就會列出 `done` 這個選項，因為 `columns` 資料本身不變，只是主看板渲染範圍縮小為三欄，選單資料來源不受影響） |
| `TaskDrawer` 的「欄位」下拉選單 | 不變，仍然包含「已完成」選項（`COLUMN_OPTIONS` 沿用 `columns.ts` 的全部四個欄位），使用者仍可透過編輯任務表單手動把 `columnId` 設為 `done` |

## 架構影響（規劃）

### 資料層／欄位定義

- `src/data/columns.ts` 的 `columns` 陣列維持四個欄位不變（`todo`/`in_progress`/`review`/`done`），因為 `TaskDrawer` 下拉選單、`TaskCard`「移動到...」選單、`/done` 頁面的欄位資訊都還需要用到 `done` 的 `title`/`colorClass`。
- 新增一個只給「看板主頁面」用的常數，例如 `BOARD_COLUMNS = columns.filter((c) => c.id !== 'done')`，只包含前三欄，用於 `App.tsx` 桌面版與手機版的渲染迴圈。

### 路由

- 新增 npm 依賴：`react-router-dom`。
- `main.tsx`（或等效進入點）包一層 `<BrowserRouter>`。
- 新增 `<Routes>`：`/` 對應現有的看板主頁邏輯（`App.tsx` 內容微調），`/done` 對應新頁面元件（例如 `DonePage.tsx`）。

### 看板主頁面（`App.tsx`）

- 桌面版/手機版的欄位渲染迴圈改用 `BOARD_COLUMNS`（三欄），不再需要「已完成」欄位相關的折疊邏輯（`isDoneCollapsed`/`toggleDoneCollapsed`/`DONE_COLLAPSED_KEY` 可以整段移除，因為已完成欄不再出現在看板上，折疊功能失去意義）。
- 新增底部拖放長條元件（例如直接寫在 `App.tsx` 或拆成 `DoneDropZone.tsx`），用 `useDroppable({ id: 'done-drop-zone' })` 註冊為拖放目標；`handleDragEnd` 需要新增判斷：當 `over.id === 'done-drop-zone'` 時，將該任務的 `columnId` 更新為 `'done'`（與既有的欄位拖放邏輯共用同一個 `updateTaskApi` 呼叫路徑）。
- 底部長條僅在桌面版顯示（`hidden sm:block` 之類的 class），手機模式不渲染。

### `/done` 頁面（新元件）

- 顯示所有 `columnId === 'done'` 的任務，用簡單的垂直清單（可複用 `TaskCard` 的呈現，不需要 `SortableTaskCard`/`BoardColumn`，因為這裡不支援拖拉排序）。
- 點擊任務開啟既有 `TaskDrawer`（`mode='edit'`），儲存後重新整理清單。
- 頁面提供返回看板主頁的連結。

### `Toolbar.tsx`

- 加入「已完成」連結（顯示已完成任務數量，例如「已完成 (3)」），點擊導覽到 `/done`。任務數量需要從 `App.tsx`／全域任務清單往下傳，或 `/done` 頁面自己重新 `fetchTasks()` 計算——沿用現有 `fetchTasks()` 已經一次拉全部任務的模式，兩個路由各自呼叫 `fetchTasks()` 即可，不需要額外的全域狀態管理。

## 範圍外（本次規劃不涉及）

- 不涉及底部拖放長條在手機模式下的替代呈現（手機模式維持用「移動到...」選單）。
- 不涉及 `/done` 頁面內任務的排序、篩選、搜尋功能，僅單純列表顯示（依 `updatedAt` 或既有 API 回傳順序即可）。
- 不涉及把「已完成」從 `ColumnId` 型別移除或修改資料庫 schema——`done` 狀態與資料表結構完全不變，只是前端渲染範圍調整。
- 不涉及 `justify-center` 裁切 bug 本身的修正（三欄後已經不會觸發這個問題，不需要額外處理safe-center）。
