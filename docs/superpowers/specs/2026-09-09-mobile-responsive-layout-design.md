# 手機版響應式版面 設計文件

> 討論日期：2026-09-09
> 狀態：**Spec only — 本文件僅記錄設計決策，待確認後進入 plan + 實作階段**

## 背景

目前看板為四欄式 Kanban（等待認領 / 處理中 / 等你確認 / 已完成），採固定寬度（`w-80`，320px）多欄橫向排列 + 拖拉換欄。這個設計是為桌面滑鼠操作設計的，在手機螢幕（例如 iPhone 17 系列，CSS 寬度約 393px）上會遇到：

1. 一次只能看到不到一欄半的內容，其餘欄位需要橫向捲動才能看到，難以一眼掌握整個看板狀態。
2. 觸控拖拉在小螢幕上精準度差，且拖到畫面外（捲動中）的欄位幾乎無法操作。

本次規劃讓看板在手機寬度下改用單欄 + 標籤切換的呈現方式，桌面版完全不受影響。

## 已確認的設計決策

| 決策點 | 選擇 |
|---|---|
| 響應式斷點 | `< 640px`（Tailwind `sm` 斷點）視為手機模式；`≥ 640px` 維持現有桌面版佈局，不做任何改動 |
| 手機模式看板佈局 | 改為單欄顯示：畫面上方有一列橫向的欄位標籤（例如「等待認領 (2)」「處理中 (1)」「等你確認 (3)」「已完成 (0)」），點擊標籤切換目前顯示哪一欄的卡片列表 |
| 桌面版拖拉邏輯 | **完全不變**——`DndContext`、`handleDragStart`、`handleDragEnd`、`@dnd-kit` 相關設定維持現狀，手機模式只是透過 CSS/條件渲染改變「看到什麼」，底層資料流一致 |
| 手機模式換欄位方式 | **不依賴拖拉**。在手機模式下的 `TaskCard` 上額外顯示一個「移動到...」按鈕，點擊後展開/彈出目標欄位選單（顯示除目前所在欄位外的其他三個欄位），選擇後直接呼叫既有的 `updateTaskApi(taskId, { columnId })` 更新，行為等同拖拉換欄，只是觸發方式不同 |
| 桌面模式是否也顯示「移動到」按鈕 | 不顯示——桌面版維持純拖拉換欄，避免混雜兩種互動方式造成介面雜訊；此按鈕只在手機模式的 `TaskCard` 渲染路徑出現 |
| 已完成欄位折疊功能 | 手機模式下沿用既有邏輯（`localStorage` 記住的折疊狀態），但因為手機模式本身就是一次只顯示一欄，折疊功能實務上意義不大——若使用者切到「已完成」標籤時該欄仍是折疊狀態，直接在標籤下方顯示「展開查看」提示，行為與桌面版一致（都是透過同一個 `isCollapsed`/`onToggleCollapse` 邏輯） |

## 佈局變更（規劃）

### `App.tsx`

- 新增一個手機模式下的「目前選中欄位」state，例如 `mobileActiveColumnId: ColumnId`，預設為 `columns[0].id`（即「等待認領」）。
- 渲染邏輯依螢幕寬度分岔：
  - 桌面（`sm:` 以上）：維持現有 `<div className="flex w-full justify-center gap-4">` 內 `columns.map(...)` 全部渲染。
  - 手機（`sm:` 以下）：改為渲染一列標籤（`columns.map` 產生按鈕，點擊設定 `mobileActiveColumnId`），標籤列下方只渲染 `mobileActiveColumnId` 對應的單一 `BoardColumn`。
- 用 Tailwind 的 `hidden sm:flex` / `flex sm:hidden` 這類 class 組合來做純 CSS 層級的顯示切換（不需要用 JS 偵測視窗寬度），確保 SSR/首次渲染一致、不會有版面閃爍問題。
- `DndContext` 包住整個看板區域（含手機模式的單欄），拖拉在手機模式下技術上仍可運作（`@dnd-kit` 本身支援觸控），只是使用者不一定會用（因為看不到其他欄位當拖放目標）；不刻意停用，維持程式碼簡單。

### `BoardColumn.tsx`

- 手機模式下欄寬需要能撐滿手機螢幕寬度，而非固定 `w-80`。改為在手機模式渲染時額外套用 `w-full`（透過 props 傳入 `isMobile: boolean`，或直接讓父層在手機模式渲染路徑用不同的 wrapper class 覆蓋寬度）。

### `TaskCard.tsx`

- 新增「移動到...」按鈕，僅在手機模式渲染（透過 `isMobile` prop 或父層條件渲染整個按鈕區塊）。
- 點擊後顯示一個簡單的欄位選單（可用原生 `<select>` 或小型下拉清單，選單選項為除目前 `columnId` 外的其他欄位），選擇後呼叫 `onMoveToColumn(targetColumnId)` callback（由 `App.tsx` 提供，內部呼叫 `updateTaskApi`）。

## 其他元件的響應式檢查（規劃）

- `Toolbar.tsx`：目前已有 `flex-col ... sm:flex-row` 響應式基礎，本次順帶檢查窄螢幕（< 640px）下中間的分頁 tabs（Dashboard/議題看板/列表視圖/甘特圖）是否會擠壓或溢出容器，必要時加上 `overflow-x-auto` 或縮小 padding。
- `TaskDrawer.tsx`：目前 `max-w-3xl` 側邊抽屜在手機寬度下應會自動撐滿（因為螢幕本身小於 max-w-3xl），但表單內各欄位（尤其「標籤」「負責人」的 checkbox 群組）需要在手機寬度下實測確認排版正常、無溢出。

## 範圍外（本次規劃不涉及）

- 不涉及手機模式下停用觸控拖拉（拖拉技術上仍保留，只是不是主要換欄手段）。
- 不涉及新增「平板模式」的第三種斷點/佈局（只分手機/桌面兩種）。
- 不涉及 Toolbar 的甘特圖/列表視圖等分頁本身內容的手機適配（那些分頁按鈕本身目前無實際功能，只是靜態 UI）。
- 不涉及 PWA/原生 App 化或離線支援。
